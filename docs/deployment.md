# Развёртывание Jenga на текущих адресах

Перенос репозитория не переключает сервер автоматически. Пока работают старые релизы.
Текущий импорт добавляет CI, но не запускает деплой без настроенного доступа.

По последней подтверждённой схеме Caddy:

- CRM: `/srv/deutsch-klub/test/crm/current` — статический сайт.
- Teacher: systemd `deutsch-klub-teacher-test.service`, reverse proxy `127.0.0.1:3101`.
- Teacher releases: `/srv/deutsch-klub/test/teacher-app/releases/`.

Эти технические имена сохраняются на сервере до отдельной миграции инфраструктуры.
Не заменяйте их простым поиском/заменой: новые каталоги и сервисы ещё не созданы.

Порядок переключения:

1. Сверить активный Caddyfile, ExecStart/WorkingDirectory systemd и current symlinks.
2. Сохранить старые ссылки current и резервные копии используемых данных.
3. Собрать оба приложения из одного проверенного commit Jenga (`npm run check`).
4. CRM: загрузить содержимое `apps/crm/dist/` в новый release текущего CRM-каталога.
5. Teacher: перенести **полный** `apps/teacher/dist/standalone/` в новый release.
   Сверить, что сервис запускает `node server.js` именно из него; если старый
   ExecStart ожидает вложенный `dist/standalone/server.js`, сохранить этот путь.
   Не смешивать исходники и standalone-структуру без проверки unit.
6. Проверить права пользователя сервиса, наличие public/fonts, иконки и client assets.
7. Атомарно переключить current (новый временный symlink + rename), перезапустить
   только Teacher unit, проверить обе страницы, вход, статические файлы и переходы.
8. При ошибке вернуть предыдущие current и перезапустить Teacher.
9. Отключить старые deploy workflow прежде, чем включать автоматический деплой из
   Jenga: иначе следующий push в старый репозиторий может перезаписать новый релиз.

Для нового CI/CD нужны секрет SSH, verified host key, host/user и проверенные пути.
Секреты хранить в GitHub Actions secrets, не в репозитории. Переиспользовать текущие
адреса; `jenga.ru`/`crm.jenga.ru`/`teacher.jenga.ru` включать только после DNS и проверки.
Сайт продукта — отдельный последующий этап, сейчас в репозитории два приложения.

Это технический перенос прототипа. Он не устраняет ограничения авторизации,
сохранения данных и разделения тестовой/рабочей среды, описанные в README.
