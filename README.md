# Jenga

CRM для школ и кабинет преподавателя в одном репозитории.
Чёрно-жёлтая айдентика, единая оригинальная иконка и переходы между приложениями.

## Структура

- `apps/crm` — React/Vite CRM; схема и черновики общей БД находятся здесь в `supabase/`.
- `apps/teacher` — React/vinext Teacher App.
- `packages/platform` — общая логика адресов приложений с тестами.
- `branding/jenga-icon.png` — исходная утверждённая иконка, без перерисовки.
- `.github/workflows/ci.yml` — проверки обоих приложений.

## Запуск

Node.js >=22.13.0; для сборки Teacher App нужен Linux с GNU timeout.
У приложений отдельные lock-файлы: React 18 и React 19 пока не смешиваем.

```sh
npm run install:apps
npm run dev:crm
# Во втором терминале:
npm run dev:teacher
```

CRM: http://localhost:5173; Teacher: http://localhost:5174.
Проверки: `npm run check:branding && npm run check`.

Демо-вход CRM: `Jenga` / `jenga2026`.
Демо-вход Teacher: `marina` / `jenga2026`.
Это демонстрационная авторизация, не защита рабочих данных.

## Связь приложений

Ссылки автоматически переключают префикс `crm.` ↔ `teacher.` на текущем домене,
а локально — порты 5173 ↔ 5174. На неизвестном домене ссылка скрыта.
Можно явно задать `VITE_TEACHER_APP_URL` для CRM и `NEXT_PUBLIC_CRM_URL` для Teacher
до сборки. Токены и параметры текущей страницы в соседнее приложение не передаются.

Целевые адреса: `jenga.ru` (сайт), `crm.jenga.ru`, `teacher.jenga.ru`.
Они не активируются автоматически этим коммитом.

**Общий репозиторий и навигация готовы; общие вход, БД и синхронизация ещё не реализованы.**
CRM сохраняет прежние локальные данные и опциональное чтение из Supabase;
Teacher работает с демонстрационным расписанием и состоянием в памяти.
SQL-черновики нельзя считать применёнными миграциями.
